# 设计依据

本框架只保留能直接支持操作决策的依据：

- **先设计后执行**：把目标、范围、权限、风险和验收在修改前显式化，可减少返工和暗中扩张。
- **完成需要独立清单**：实现清单回答“做什么”，完成清单回答“凭什么算完成”，两者不能互相替代。
- **单一权威源**：状态和规则多处复制会产生漂移；链接比复制更可靠。
- **按风险分级**：验证、备份和协调成本应随影响与不可逆性增长，不能让所有任务支付同一固定成本。
- **图式联动**：多节点任务的失败常发生在接口和交接边，而不只发生在节点内部，因此节点验证与边验证必须分开。
- **最小权限与数据保留**：删除工作流组件不等于授权删除用户数据；原生历史、人工内容和密钥需要独立保留边界。
- **可证伪验证**：检查器需要反例自测；只有真实环境证据才能支持真实行为结论。

这些原则是规则设计约束，不是对每个任务强制创建额外文档的理由。
