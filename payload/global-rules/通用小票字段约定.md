# 通用小票模板字段接口约定

## 适用范围

只规范快消品、美国轮胎、加拿大轮胎、摩托车、机油五类业务的**通用小票模板**所接收的店铺表、数据表接口：列名、顺序和两表映射。这不是每张原票的票面字段要求，也不是每笔数据、每一行都要把这些字段填满或印出来的要求。原票实际有什么字段，以该票及其专属规则为准；不能因为通用模板有某列，就从原票中猜造该项。模板允许空的字段按实际留空；确属必填而缺来源的，按缺字段规则报错，不填假值。本约定不自动迁移旧工作簿、既有活动表或出票代码。

## 通用模板的店铺表接口：九列

通用模板接收店铺表时，列名和顺序为：

```text
店铺编号	店铺名称	店铺地址	店铺城市	店铺州	店铺邮编	店铺电话	店铺邮箱	店铺网站
```

## 通用模板的数据表接口：二十三列

通用模板接收数据表时，基线列名和顺序为：

```text
邮箱	名	姓	地址	城市	州	邮编	电话	商店编号	商店名称	商店地址	商店城市	商店州	商店邮编	商店电话	店铺邮箱	店铺网站	商店人员名	商店人员姓	商店人员名1	商店人员姓1	商店人员名2	商店人员姓2
```

前八列是顾客信息；第九至十七列是店铺信息；最后六列是三组人员姓名。人员的名和姓按组配对；没有真实信息时不编造。这 23 列是模板数据接口，不是要求每张原票都能采集到 23 项。字段是否必填、空值如何处理及哪些内容显示在票面，仍由目标模板的实际消费者和对应原票规则决定。

## 两表映射及已有消费者

仅在两表对接、构造通用模板的数据表时，才把店铺表前七列 `店铺编号/名称/地址/城市/州/邮编/电话` 逐项映射到数据表的 `商店编号/名称/地址/城市/州/邮编/电话`；`店铺邮箱`、`店铺网站` 在两表中保持同名。不要把 `店铺*` 七列原样再追加到数据表，也不要把用户指定的 `店铺邮箱/店铺网站` 静默改成 `商店邮箱/商店网站`。这项映射不要求任何原票采用同样字段名。

现有模板若读取 `商店官方名称`、`商店邮箱`、`商店网站`，或通用小票绘制入参使用 `店铺名称`，只在该消费者的接入映射中处理差异；本约定不自动改旧表头、代码、历史输出或专用票规则。用户确认：旧正式数据表继续保留 `商店官方名称`，以免影响尚待修改的其他代码；以后新建的标准化套用数据表使用 `商店名称`，而不是反向把新字段命名成旧别名。原票实际出现的额外税号、车辆、商品、支付等内容由对应票种单独声明和处理，不因不在上述 9/23 列中就丢弃。

## 复制／套用数据表时的字段替换

复制源票的数据表只得到一份**结构起点**，不能把源店铺、人员或票面事实当作目标票事实。发布前逐个目标票种执行：

1. 先列出目标票实际读取的数据表、店铺表字段及消费者；保留目标票正式数据表原有输入列和顺序。上述 9/23 列只在采用通用模板接口时作为映射基线，不能据此给专用票增删或重排表头。目标票需要的其他客户、人员、支付、车辆等输入字段按本票规则保留。
2. 顾客前八项来自目标数据行，不从源店铺表覆盖。将目标店铺表的九项按上节语义逐项映射至目标数据行已有的店铺字段；`商店官方名称` 等别名只在目标消费者的接入层映射。源票的店号、店名、地址、州、联系方式必须从目标行清出，不得沿用为目标票身份。目标来源缺失时按本票必填／可空规则处理，不复制源值或编占位值。
3. 三组人员姓名只从目标票允许的真实来源取得，名、姓成组对应；无来源且可空则留空，必填则停止。源票人员姓名不得随工作簿套入。加拿大 GST/PST 占位不在 9/23 接口中；真实税行仍由本票规则负责。
4. 逐行对照目标店铺编号与店铺字段，检查源店铺残留、客户／店铺字段错位、别名映射、公式与格式、非目标 Sheet；再用目标票自己的 `全自动.py` 跑一张，核对票面和活动结果表。仅复制了工作簿、只通过表头检查或只跑源票，都不算套用完成。

母表商品名改变时，先定位该活动页及其实际消费者，再逐消费者核对母表、目标主采集行、允许复用的副采集行及套用项目源样本。只同步已确定的同一商品事实；票种 POS 名、编号、价格和字段取舍仍由各自规则／证据裁定。改后记录旧值→新值与对应行，复开每张受影响工作簿核对非目标区，并用真实入口验证；不得仅因源票改名就跨票机械复制短名或编号。

## 所有发票的多主商品要求

快消品、机油等每张原票和套用票都必须能在同一张票上处理多条主商品；主商品数量、字段形态和票面排列由本票规则及已核实采集数据决定，不把副商品冒充第二主商品，也不把某票的固定两列上限当成所有票的通用上限。`全自动.py` 应把本次选中的主商品按采集顺序单独保留，再构造实际出票的主加副商品；模板绘制全部主商品，结果表逐项回写全部且仅回写主商品明细。单主商品成功运行只证明兼容旧数据，不证明多主支持；每张票需要另有同票至少两主商品的隔离全自动回归，并核对 PDF、结果表顺序、各自主商品数量和行金额。

## 套用票的出票与结果表边界

有主、副采集表的套用票，`全自动.py` 分别保留本次选中的主商品列表和实际出票的主加副商品列表：前者按主采集行及行内商品顺序，后者按该票规则排序。`发票模板.py` 只绘制同一次生成的日期、编号、身份、支付、商品与金额快照，不自行重抽。活动结果表的 `商品名称-1/商品数量-1/商品总价-1` 等逐商品字段及 `商品款数` 只来自选中的主商品；`商品总价` 是该主商品在票上的行金额，若采集字段是单价才乘数量。副产品的名称、单价、数量、行金额和逐项编号只用于票面与整票计算，不写成结果表的商品明细。整票税后金额、实际发票编号和真实生成路径仍按票面结果写回，未生成的第二张票或附票不得造路径。

隔离运行真实 `全自动.py` 时，测试输入数据表和结果表要保留以供复核；不得在测试后清空测试行，也不得为测试改坏正式数据表。无有效输入行时记录缺口，不能把源票身份或店铺资料编成目标票的正式交易。

## 加拿大 GST/PST

GST、PST 在这两套通用模板表中基本只是占位，**不列为上述 9/23 列，也不为填表虚构值**。这只针对模板字段接口；加拿大原票确实需要的 GST/PST/HST/QST 税额计算、税号或票面税行，仍按该原票和专属规则处理，不能因通用模板不列占位字段而删除真实税行。
