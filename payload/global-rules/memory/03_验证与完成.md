# 验证与完成

## 验证层级

按任务风险选择足够而不过量的验证。以下是全库唯一的验证词表，入口、模块和模板一律引用它，不得另立：

- 静态：语法、格式、Schema、链接、配置可解析。例：Python 编译或 AST 通过，xlsx 能复开，JSON 能复读。
- 针对性：受改函数、命令、文件或规则的直接测试。例：真跑这张票自己的全自动生成一张 PDF。
- 联动：节点输入输出和边契约。例：采集表、数据表、任务配置的活动名和字段一致，数据链能走通。
- 回归：直接消费者、反向引用、兼容路径。例：改了共享工具，同链其他票各跑一张。
- 真机/外部：只有真实环境证据才能证明真实行为；模拟结果必须明确标为模拟。例：对着原票逐项看字段、字体、金额，视觉核对渲染结果。

能真跑就真跑，别猜。条形码数条数定码制、金额算乘积、字体看原票，都是真机层的事。

## 证据表达

每项证据至少包含：执行对象、方法、结果、时间或当前版本、未覆盖范围。失败和跳过同样要记录原因。

报告里的统计表列全所有行，不挑「关键行」省略；每行数值照列，含 0 和小值。

状态只用：

- 完成：验收与必需验证全部通过。
- 部分完成：已有可用交付，但仍缺明确范围。
- 待验证：实现存在，关键证据缺失。
- 阻塞：外部条件或授权阻止继续，并写清解除条件。

禁止用「应该、看起来、理论上」替代完成证据。

## 最终完成清单

任何实质任务在宣告完成前都必须逐项核对。微任务可合并为一行证据；中/大任务必须保留可复核记录。

1. 目标、非目标、验收和交付物逐项一致。
2. 所有必需节点已完成；所有 `→ / ↔ / ∥ / 扇出 / 汇聚` 边契约已验证。
3. 静态、针对性、联动、回归和真机验证按设计执行，结果可复现。
4. 删除/覆盖集合与保留集合复核通过，用户数据与原生历史未受损。
5. 直接消费者、反向引用、兼容性和回退路径已验证；目标区域之外没有连带改变。
6. 未验证项、已知限制、失败和外部阻塞已如实列出，未把「待验证」写成「完成」。
7. 权威状态和变更记录已更新，备份/回退点路径已记录，临时文件按约定处理。
8. 最终答复包含结果、验证证据、备份路径、保留/删除范围和剩余问题，能让用户独立判断任务是否真的完成。

任何一项必需检查未通过，就不能把整体状态写成完成。

填写载体见 [templates/完成清单填写表.md](../templates/完成清单填写表.md)。

## 失败处理

测试失败先判断是实现失败、环境失败、断言过期还是范围变化。修复后重跑受影响层和必要回归；不得只重跑最容易通过的检查。排查方式见 [07](07_子代理与工具.md)。
