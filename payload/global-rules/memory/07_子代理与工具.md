# 子代理与工具

## 子代理是探子

- 子代理用来做「宽而重」的读取：全项目扫描、多处并行核验、需要隔离上下文的探索。只有在能减少主线程上下文污染、提高并行度或提供独立核验时才派。
- 微任务不派；小任务只有净收益明确时派一个窄任务；中/大任务或复杂联动才积极派。
- 共享写入由主执行者串行完成；子代理只读、只报告，不直接改用户文件。
- 派发前写清要找什么、范围多大、回什么格式；回来的结论要抽查核实，不照单全收。
- 不为了「多代理」本身增加启动等待。

## 何时直接处理

- 已知位置的小文件、少量代码或单一事实。
- 即将修改的具体代码。
- 派发、等待和复核的成本不低于自己读取。
- 阶段 A 确认属于本任务地基的架构文档、设计文档、交接备忘录，无论多长都由主执行者完整读取；不能仅凭文件名或项目里存在该文档，就让微/小任务无条件全文读取。

## 批处理与自动化

- 确定性的批量脚本（跑几十个项目的全自动、批量转换、批量核对）用 shell 循环或单个 Python 脚本顺序执行，不套多代理编排或 workflow；没有推理价值，只会更慢更脆。
- 批量任务先在 1 到 3 个样本上真跑通过，再放大到全量；全量后做复扫统计，表格列全所有行。
- 批处理读源文件，不用缓存；用户说数据更新了就重读。

## 失败排查方式

- 先读源码、机制、调用链、手册、报错原文，定位根因后再改；不反复试参数碰运气。
- 区分实现失败、环境失败、断言过期、范围变化，再决定改哪里。
- 找不到根因就停下报告已排除的可能，不硬改。

## 浏览器连接与采集回退

适用于所有加载本全局规则的项目中，用户已经授权的网页查询、采集和浏览器操作；这是通用操作要求，不限于机油或快消品。不扩大当前任务的业务范围，也不代替平台权限或实际工具连接。

1. web 或内置浏览器能完成当前查询时正常使用。web 不可用、内置连接列表为空，或目标页面必须交互才能取得内容时，直接进入 DrissionPage（简称 DP）路径；不得仅因没有内置连接就让用户先手动开浏览器、报告无法采集或跳过整个任务。
2. 固定连接地址为 `127.0.0.1:9555`。先检查该端口是否提供有效的 Chrome 远程调试连接；不能只看有无 Chrome 进程或端口是否被占用。
3. 已有可连接的 Chrome：使用 DP 接管并复用，不重复启动。只操作当前任务相关页面，不关闭或改动用户其他标签页，不把个人浏览历史和登录数据当作采集材料。
4. 没有可连接的 Chrome：自动定位本机 Google Chrome，启动可见窗口，启用 `--remote-debugging-port=9555`，使用独立、持久化的自动化用户目录，再由 DP 连接并打开当前任务目标页面。无需用户重复确认“打开浏览器”。普通 Chrome 即使已经打开，未启用该调试端口也不算可接管；不得为此关闭用户普通窗口或占用其默认用户目录。
5. 固定使用 9555，不擅自随机换端口。该端口若被非 Chrome 调试服务占用，明确报告冲突，不杀进程、不抢占。连接只供本机使用，不向局域网或公网暴露调试端口。
6. 优先复用已有 DP 环境和启动/接管代码；缺依赖、Chrome 未安装、启动失败、调试连接失败应分别记录实际原因。依赖安装按当前任务授权处理，不能把缺依赖误报成“电脑没有浏览器”。
7. 只有实际连接成功并确认目标页面已经打开，才可说“浏览器已打开，可以人工处理”。验证码或登录需要用户操作时，保留窗口并通知用户；人工窗口从页面实际打开后开始计时，最多等五分钟，期间保持简短进度更新。用户处理完成后继续；五分钟未处理则保留页面与待办记录，先处理其他可执行项，后续从断点恢复。不得绕过验证码或访问控制。
8. 普通工具不可用与平台明确禁止是两回事。平台明确禁止该操作时立即停止该路径并如实报告，不通过 DP、换命令或换端口绕过。尚未成功打开页面时，不启动人工倒计时，不声称“正在等用户验证”。
9. 验证记录区分“规则已写入”“DP 已连接”“目标页面已打开”“采集数据已取得”；逐项以实际结果为准。写入本规则不表示已经安装 DP、启动 Chrome、建立内置连接或完成采集。
