# 规则治理

## 单一正文

`CLAUDE.md` 只保存权威优先级、路由、执行顺序和加载指引；`STATE.md` 只保存动态状态；`变更记录.md` 只保存改动历史；`memory/README.md` 只保存索引；7 个模块各自拥有一类细则；模板只定义填写载体。

用户级 Claude/Codex 入口只保存一句指向 `CLAUDE.md`，不复制正文；两个工具共用的内容（子代理策略、备份、沟通）一律放本库模块。

[任务设计清单](01_任务设计与联动.md#任务设计清单)与[最终完成清单](03_验证与完成.md#最终完成清单)的正文各只有一份，其余位置一律链接引用。发现重复时保留最清晰的权威正文，其余改为链接或删除。

`tools/check_docs.ps1` 的单一正文注册表强制这一点：注册标题出现在非权威文件即 FAIL。新增需要唯一正文的章节时，同步更新注册表。

## 术语一致

验证层级只用 [03 的词表](03_验证与完成.md#验证层级)：静态 / 针对性 / 联动 / 回归 / 真机。状态只用：完成 / 部分完成 / 待验证 / 阻塞。检查器的弃用词表清单会拦截已被取代的说法；淘汰一套说法时，把旧写法加进该清单。

## 新规则准入

新增长期规则前回答：

- 是否来自稳定、可复用的用户偏好或已验证事实？
- 是否已有权威正文？
- 触发条件、适用范围、例外和失效条件是什么？
- 能否执行或验证，还是仅为建议？
- 会不会让微/小任务承担不必要成本？

一次性要求、某次工具版本、无证据推断和纯历史过程不进入长期规则。不为库内不存在、也无法验证的组件设立约束。

## 冲突处理

先区分事实冲突、范围冲突、版本冲突和优先级冲突。高优先级覆盖低优先级时记录替代关系；过时规则直接删除或标为历史，不保留两个活动版本。平台指令冲突时以平台为准，并在必要时向用户说明。

## 规则变更验证

规则或加载机制变化最低按中任务：

1. 改前按 [操作与变更控制](02_操作与变更控制.md#备份铁律) 保存本次受改文件及回退清单。
2. 扫描入口、模块、模板、用户级 Claude/Codex 入口，以及项目入口里对本库路径和章节的引用。
3. 跑 `tools/check_docs.ps1`：链接、锚点、孤儿、全库 frontmatter、单一正文、术语、状态行。
4. 验证两个用户级入口仍是一句指向、项目入口引用的路径仍存在。
5. 用反例测试检查器，避免只会报绿。新增检查必须同时新增能复现该缺陷的反例用例；改不了颜色的用例不算用例。
6. 更新 `STATE.md` 和 `变更记录.md`，写明备份路径和检查结果。

## 定期清理

优先删除无消费者、无触发条件、与权威正文重复、无法执行或长期造成流程膨胀的规则。历史价值由 [变更记录.md](../变更记录.md) 和 code_back 备份承担，不让主规则库变成档案馆。

`review_after` 到期由检查器告警（不阻塞）。复审日期按模块变更频率错开，避免同日集中到期。
