# 全局规则：任务设计、联动执行与完成闭环

## 权威与优先级

本目录是本机 AI 协作规则的唯一活动权威库，本文件是唯一强制执行入口，Claude 和 Codex 共用。用户级 Claude/Codex 入口只保存一句指向本文件，不复制正文；项目自己的 `CLAUDE.md` / `AGENTS.md` 只约束该项目。

平台系统/开发者指令高于本地规则；用户当轮明确指令高于项目与全局默认；项目规则高于全局默认，但只在其项目范围内生效。

- 默认简体中文、UTF-8；跟用户说话用大白话，不用术语和代号选项，细则见 06。
- 入口负责路由，模块负责细则；同一规则只保留一份正文。
- 文档里写了「自动、已加载、已验证」不等于事实，必须有真实宿主或证据。
- Claude/Codex 原生会话历史属于用户数据，不得因清理工作流、配置或含有某个词而删除、截断或改写。
- 本库不使用 git。版本和回退由 `{{BACKUP_ROOT}}/` 备份目录和 [变更记录.md](变更记录.md) 承担。

## 阶段 A：最小读取

依次读取：本文件 → [memory/README.md](memory/README.md) 的问题路由 → 用户当轮指令 → 项目入口（`CLAUDE.md` / `AGENTS.md`）声明的必读顺序 → 项目 `.ai-session/handoff.md` 顶部状态块（若存在，只读前 40 行）。

只用标题、索引或搜索定位项目权威载体；不因文件名、锚点或目录存在就通读项目长期记忆（`_记忆/`、`memory/`、长变更日志）。项目入口声明的长文档，只有中/大任务且确属本任务地基时才全文读取。

然后给出一句路由结论：

`微/小/中/大｜局部/全局｜单线/联动拓扑｜常规/高风险`

- **微**：一个原子动作，范围和验收明确。例：改一张票的一个字段坐标。不建持久 Plan、不全项目扫描、不派子代理。
- **小**：一个会话可闭合，涉及少量相邻文件和直接消费者。例：给一张票加一个服务行并跑通全自动。
- **中**：多步骤、多目录、多消费者、迁移或批量变更。例：改根目录共享工具、同步二十几个项目的采集表。须持久化计划、建动作前回退点、分项验证。
- **大**：架构重构、跨项目大改、不可逆外部动作或正式交付。须分阶段设闸门和交付级验证。
- **局部/全局**：是否改变共享入口、规则、契约、Schema、公共工具或公共能力。
- **单线/联动**：是否有多个必须协调的节点。写法 `A → B`、`A ↔ B`、`A ∥ B`、`A → {B,C}`、`{A,B} → C`。做票链本身就是 `采集表 → 数据表 → 模板 → 全自动 → PDF`。
- **常规/高风险**：删除、覆盖、移动、手工数据、权限密钥、生产、财务法律或难回滚。

升档触发器，只升不降：全局行为变化、跨项目联动、高风险 → 最低中任务；不可逆外部动作 → 大任务。节点保留自己的规模，父任务只保存共同目标、边契约和总状态。

### 微任务快速通道

用户只指一处、改法明确、可逆、不碰共享文件时：只读本文件、目标票自己的规则和代码，不读项目大文件；一句话复述范围后直接动手；改前备份该文件；改后跑该票的针对性验证并报告。

## 阶段 B：按设计执行

开工先做三件事：一句话复述我理解的范围和不做什么；小及以上任务列出这次要走的步骤请用户点头，拿不准的先问；按 02 备份再动手。

1. 修改前完成[任务设计清单](memory/01_任务设计与联动.md#任务设计清单)。
2. 动作前过[操作与变更控制](memory/02_操作与变更控制.md)的动作前门：目标、授权、备份、保留边界和回退点。
3. 只修改用户指定的范围和已纳入设计的权威源；发现关联问题只报告，不顺手修。
4. 节点验证 → 边契约验证 → 整体回归；能真跑一张就真跑，不猜。
5. 宣告完成前逐项核对[最终完成清单](memory/03_验证与完成.md#最终完成清单)。

停止条件：授权范围外、目标未解析、回退点缺失、证据冲突、数据缺字段或为零、出现未纳入设计的消费者时，停止并回到设计清单重新路由或询问用户。
